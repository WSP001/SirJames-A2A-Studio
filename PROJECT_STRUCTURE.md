# Project Structure & Directory Standards
# Sir James Adventures Book002

This document defines the definitive directory structure, naming conventions, and read/write permissions for the project. 
It is designed to support a hybrid architecture:
1. **Core Pipeline**: Node.js + Netlify Functions (Production)
2. **Data Processing**: Python + Jupyter/Colab (Research & Assets)
3. **Frontend**: React + Vite (Presentation)

---

## 📂 Directory Map

### `src/` (Frontend Source)
* **Purpose**: React application source code.
* **Permissions**: Read/Write (Devs).
* **Contents**:
  * `components/` - Reusable UI elements (CostMeter, CreativeHub).
  * `assets/` - Static images/icons not generated by AI.
  * `pages/` - Route components.

### `netlify/functions/` (Serverless Agents)
* **Purpose**: TypeScript/Node.js backend logic (The "Agents").
* **Permissions**: Read/Write (Devs).
* **Naming**: Kebab-case (e.g., `curate-chapters.ts`, `text-to-speech.ts`).
* **Subfolders**:
  * `lib/` - Shared utilities (telemetry, memory, storage).

### `pipelines/` (Orchestration)
* **Purpose**: Manifests and runners for the content generation pipeline.
* **Permissions**: Read/Write (Devs & CI/CD).
* **Contents**:
  * `*.yml` - Pipeline manifests (e.g., `a2a_manifest.yml`).
  * `scripts/` - Logic for pipeline steps (e.g., `ffmpeg_compile.mjs`).
  * `run-manifest.mjs` - Main executor.

### `notebooks/` (Research & Data)
* **Purpose**: Jupyter/Colab notebooks for experiments, data cleaning, and one-off tasks.
* **Permissions**: Read/Write (Data Science).
* **Contents**:
  * `colab_setup.py` - OneDrive/Drive mounting scripts.
  * `experiments/` - Scratchpad notebooks.

### `workers/` (Python Background Jobs - Planned)
* **Purpose**: Heavy python processing (not suitable for Netlify Functions).
* **Permissions**: Read/Write.
* **Contents**:
  * `manifest_runner.py` (Future python equivalent of run-manifest).
  * `processors/` - Image/Audio manipulation logic.

### `scripts/` (DevOps & Utilities)
* **Purpose**: Shell/PowerShell scripts for environment checks and deployment.
* **Permissions**: Execute (CI/CD).
* **Naming**: CamelCase (PowerShell) or kebab-case (Bash).

### `public/` (Output & Assets)
* **Purpose**: Static assets served by the web app.
* **Permissions**: Write (Pipeline), Read (Browser).
* **Contents**:
  * `week44/` - Generated chapter content (images, audio, json).

---

## 📝 File Naming Conventions

* **TypeScript/JavaScript**: `kebab-case.ts` (e.g., `curate-chapters.ts`)
* **React Components**: `PascalCase.tsx` (e.g., `CostMeter.tsx`)
* **Python Scripts**: `snake_case.py` (e.g., `worker_runner.py`)
* **PowerShell**: `Verb-Noun.ps1` (e.g., `Check-NetlifyToken.ps1`)
* **Config**: `snake_case.yml` or `kebab-case.json`

---

## 🛡️ Permissions & Schema

| Directory | Owner | CI/CD Action | Notes |
|:---|:---|:---|:---|
| `src/` | Frontend Team | Build | Vite build target |
| `netlify/` | Backend Team | Deploy | Deployed as Serverless Functions |
| `notebooks/`| Data Team | Ignore | Do not deploy to production |
| `public/` | Pipeline | Sync | Generated content lands here |
